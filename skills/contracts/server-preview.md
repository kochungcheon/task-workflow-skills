# 서버 미리보기 · 브라우저가 없는 실행 환경

`visual-explainer` 원본의 HTML 생성 규칙을 따른다. 이 패키지에서는 서버에 Chrome/Chromium 또는 자동 브라우저 도구가 없을 때 아래 경로를 사용한다. 원본 스킬의 자동 화면 검사는 실행 환경에 브라우저가 있을 때 계속 수행한다.

1. `maps/view.src.html`과 필요한 이미지·글꼴 등 자산을 준비한다. 키트 마커가 있는 페이지는 `node <설치된 visual-explainer>/kit/render.mjs maps/view.src.html --no-check`로 `maps/view.html`을 생성한다. `--no-check`는 브라우저 검사만 건너뛴다. 렌더러의 CSS·JS·SVG 삽입과 소스 오류 검사는 그대로 실행된다. 생성 실패나 `✗`는 수정한다. 상대 경로로 참조한 자산은 HTML과 함께 제공한다. 키트 마커가 없는 독립 HTML도 실제 자산 경로를 확인한다. `.src.html`만 서버에 올려 완성본으로 취급하지 않는다.
2. 지도 디렉터리에 이미 실행 중인 서버가 있으면 제공 경로와 응답을 확인해 재사용한다. 없으면 점유되지 않은 포트를 골라 그 디렉터리에서 미리보기 서버를 실행한다. 예: `python3 -m http.server 3000 --bind 0.0.0.0` (`3000`은 빈 포트일 때만 사용). 앱·API 서버도 기존 인스턴스를 확인하고 별도 빈 포트에서 실행한다. 예시 `3001`은 고정값이 아니다. 서버가 종료되면 다시 실행하거나 상태를 대기로 돌린다.
3. `preview_internal_url`(서버 내부 접속 주소, 예: `http://127.0.0.1:3000/view.html`)과 `preview_user_url`(사용자가 실제로 열 수 있는 포트 전달 주소)을 구분한다. 앱의 `app_internal_url`·`app_user_url`도 따로 기록한다. 포트 전달 환경에서는 내부 주소를 사용자 주소로 추정하지 않고 실제 제공된 URL을 사용한다. URL이 아직 없으면 `미확인`으로 적는다. 서버 실행 명령·디렉터리·포트·재사용 여부를 지도 색인이나 인계 기록에 남긴다.
4. 내부 주소의 HTTP 상태(예: `200`)와 HTML·자산 응답을 확인하고 결과를 기록한다. 이는 **서버 응답 확인**이다. 사용자가 실제 브라우저에서 연 화면, 레이아웃·텍스트·링크·동작 확인은 별도 **화면 확인**으로 기록한다. 사용자의 확인 발언이 없으면 `pending`이다. 자동 브라우저 검사를 실행하지 않았다면 `미실행: 브라우저 없음`으로 남긴다.
5. 앱 기능의 수동 E2E와 자동 브라우저 E2E는 지도 화면 확인과도 별개다. 각 시나리오의 수행자·행동·관찰 결과를 `task-evidence`에 남긴다. 필수 자동 E2E가 지정된 과제는 수동 확인만으로 그 검사를 통과 처리하지 않는다.

미리보기 주소를 사용자에게 전달하고 화면 확인을 기다리는 동안 지도 산출물은 생성 완료로 기록할 수 있다. 화면 확인은 `pending`이며, 기능 구현·TDD 진행을 브라우저 부재만으로 막지 않는다. 지도 HTML 자체를 생성할 수 없거나 필수 자산이 누락되면 실제 누락 항목을 `blocked`로 보고한다.
