# 현재 결과를 근거로 인계하기

[공유 계약](../contracts/task-workflow-v1.md)의 `Evidence`와 `ToolResult`를 읽는다. 입력은 현재 과제·지도·코드 식별값과 실제 실행 기록이다. `learning-review`에서는 같은 계약의 `LearningNote`와 실제 사용자 응답도 읽는다. 선택한 모드의 결과를 반환하며 작업 상태 변경과 다음 과제 선택은 호출자가 맡는다.

## handoff · 구현 결과를 넘길 때

1. 보고된 변경을 실제 파일과 대조하고 현재 과제의 인수 기준에 연결한다. 선택 이유와 사용자에게 보이는 변화부터 짧게 쓴다. 해커톤·시험 대비에서는 원문 요구·동작 경로·실제 선택 이유·실패 조건·검증 근거를 과제 파일에서 현재 코드에 맞추고 handoff에서 연결한다. 공통 결정은 전체 계획의 결정 ID를 참조하고, 해당 선택이 실제 코드·객체 지도·HTML에 같은 상태와 이유로 반영됐는지 확인한다. 구현 결과가 초기 절충 예상과 다르면 계획의 결정을 정정하도록 호출자에게 알린다.
2. TDD의 실패/통과 기록을 확인한다. 어느 기대 동작이 왜 실패했고 어떤 변경 후 통과했는지 기록한다. 가져온 로그의 시간 순서만으로 증명할 수 없는 부분은 미확인으로 둔다. 관련 회귀 결과와 미실행 검사는 별도로 적는다.
3. 두 지도의 코드·과제 버전과 현재 산출물의 식별값을 대조한다. 오래된 지도나 변경 전 테스트를 현재 결과의 근거로 합치지 않는다.
4. 공동 E2E를 위한 진입점, 준비 데이터, 행동, 독립적인 기대 결과, 정상/관련 실패 경로를 적는다. 단위/통합 테스트와 실물 경로의 확인 범위를 구분한다.
5. `evidence/<task_id>/handoff-<시도>.md`에 기록한다. 설명 문장은 [simple-english 문서 어댑터](../contracts/components.md#simple-english-문서-어댑터)로 점검하고 실행 사실·근거를 보존한다. 필수 구현 검사·지도 정합성이 충족되면 `verdict: ready_for_joint_e2e`, 아니면 `needs_work` 또는 `blocked`를 반환한다. 공동 E2E 실행 여부는 별도 결과이며 이 모드로 검증 완료를 판정하지 않는다.

## joint-e2e · 사용자와 실제 경로를 확인할 때

1. 현재 handoff와 사용자가 함께 확인할 시나리오를 읽는다. 기존 프로젝트의 실행 명령과 허용 도구로 앱·API·CLI 등 실제 진입점부터 결과까지 실행한다. 외부 경계를 대체했다면 어느 구간인지 명시한다.
2. 입력/준비 상태, 수행자, 실제 행동/명령, 기대·관찰 결과, 실행 코드 식별값, 근거 파일, 환경·대체 범위를 시나리오별로 기록한다. 실행 불가·부분 확인은 `blocked` 또는 `partial`이며 pass와 구분한다.
3. 사용자가 어느 결과를 확인했는지 대화의 실제 발언/시점을 연결한다. 에이전트의 자동 실행 결과만 있으면 `human_confirmation: pending`이다. 시간 경과나 다음 작업 요청 자체를 사용자 확인으로 채우지 않는다.
4. `evidence/<task_id>/joint-e2e-<시도>.md`에 `pass | fail | partial | blocked`와 원인을 반환한다. 이전 실패 기록을 보존한다. 실패 시 현재 과제에서 재현할 조건과 기대 차이를 제시하고, 코드 수정은 구현 단계에 맡긴다.

근거가 부족하면 필요한 실행/자료를 명시한다. 테스트 요약 문구만으로 실행 사실을 생성하거나, 사용자 수행·확인을 대신 기록하지 않는다.

## learning-review · 기능 설명과 복습 지점

1. 현재 과제·지도·관련 코드와 실제 사용자 설명을 대조한다. 입력부터 결과까지의 흐름, 핵심 선택의 이유를 각각 확인한다. 현재 버전과 연결할 수 없는 설명은 미확인으로 남긴다.
2. `tasks/<task_id>.md`의 이해 기록에 사용자 설명 또는 발언 참조, 설명 대상 식별값, 확인한 부분, 막힌 부분·오해, 관련 노드/코드를 적는다. 사용자가 말하지 않은 내용은 에이전트의 추정으로 구분한다.
3. 필요한 짧은 보충과 다시 볼 질문·정확한 문서/코드 위치를 기록한다. 사용자의 최초 설명, 에이전트 보충, 재설명 결과를 구분해 보존한다. 에이전트가 답을 설명한 것만으로 사용자 이해를 완료 처리하지 않는다.
4. `LearningNote`의 기준으로 `learning_status`를 반환하고 `plan.md`의 복습 색인을 해당 기록에 연결한다. 입력 부족은 `status: blocked`, 기록을 작성했으면 `status: ok`인 `ToolResult`를 반환한다. `learning_status`는 기능의 `verdict`·`human_confirmation`·작업 상태와 별개이며, 다음 기능 진행은 호출자가 판단한다.
