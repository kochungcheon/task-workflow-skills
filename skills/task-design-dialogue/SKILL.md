# 사용자와 설계를 왕복하기

입력은 원본 요구·기존 코드·`plan.md` 초안·현재 작업이다. 출력은 `plan.md`의 결정 ID·이유·남은 가정과, 작업/지도/검증 지점에 반영할 변경 요약이다. 단독 설계 대화에도 쓸 수 있다. 작업 상태 전이와 코드 구현은 호출자가 맡는다. [공유 계약의 PlanNote](../contracts/task-workflow-v1.md#plannote--대화-기반-계획의-선택-확장)를 따른다.

1. 원문·코드·관련 문서에서 확인되는 사실은 직접 조사해 근거를 붙인다. 요구가 정한 동작을 열린 설계 문제로 다시 묻지 않는다. 작업 경계·정합성·실패 처리·검증 경로를 바꾸는 선택을 찾아, 선행 결정이 끝나야 판단할 수 있는 항목은 뒤로 둔다.
2. `plan.md` 초안에서 **지금 판단 가능한 중요한 쟁점 하나**를 사용자에게 보여준다. 질문의 배경, 현실적인 선택지의 장단점, 각 선택이 실제 입력·실패 상황에서 어떻게 달라지는지, 에이전트의 추천과 이유를 짧게 설명한다. 대안이 더 나은 조건도 함께 제시한다. 사용자가 이미 준 목표·제약·선택을 재질문하지 않는다.
3. 사용자의 답·질문·반론을 받아 전제, 실패 조건, 포기하는 점을 함께 검토한다. 첫 답에 기계적으로 동의하거나 같은 질문을 반복하지 않는다. 필요하면 설계안을 수정해 다시 보여주고, 그 답으로 열린 후속 쟁점만 이어서 묻는다. 사용자가 더 깊게 논의하려 하면 이어가고, 판단을 위임하면 에이전트 선택으로 표시한다.
4. 결정마다 `D01` 같은 ID, 선택·이유, 실제 검토한 대안과 더 나은 조건, 사용자 합의/에이전트 선택/미확인 상태, 관련 요구·작업·객체 책임, 바뀐 검증 지점을 `plan.md`에 압축한다. 대화 전문을 복제하지 않는다. 미확인 가정은 ID·영향·반영 위치·확인 시점으로 남긴다. 현재 구현의 구조나 인수 기준을 바꾸는 미결정은 해결 전이라고 호출자에게 알린다.
5. 현재 기능의 설계·검증 경계가 설명 가능해지면 결정 요약과 남은 쟁점을 사용자에게 보여주고, 호출자에게 지도와 작업 MD에 반영할 변경을 전달한다. 후속 작업의 쟁점은 해당 작업 전에 다시 연다. 전체 가능한 질문을 끝내려고 구현을 무기한 미루지 않는다.

이 도구는 `maps/view.html`을 직접 고치거나 TDD·E2E 통과를 판정하지 않는다. 지도 반영은 `task-maps`, 구현 결과와의 대조는 `task-evidence`가 맡는다.
