# 지금까지의 작업을 한 문서로 읽기

[공유 계약](../contracts/task-workflow-v1.md)의 `ReviewBrief`와 `ToolResult`를 읽는다. 입력은 원본 과제, 현재 `plan.md`, 작업 MD, 두 지도, 실제 코드, handoff·공동 E2E·LearningNote다. 출력은 `.workflow/<과제명>/review.md` 하나다. [양식](assets/review.md)을 참고한다. 이 스킬은 단독 호출할 수 있고 `task-delivery`가 진행 중 호출할 수도 있다. 작업·검증·학습 상태의 원본과 다음 과제 선택은 각 담당 스킬에 둔다.

## 만들고 갱신하기

1. 요구·계획·작업·지도·실제 코드와 검증 기록을 대조한다. 기준 시점과 `plan_revision / map_revision / code_ref`를 명시한다. 코드나 기준이 바뀌어 이전 검증이 현재 상태를 뒷받침하지 못하면 해당 항목을 `재확인 대기`로 표시한다. 근거가 없는 완료는 만들지 않는다.
2. 30초 요약, 현재까지의 기능·공동 E2E·설명 상태, 입력→결과 경로, 중요한 결정의 이유·대안이 나은 조건, 확인한 검사·미검증 범위를 원본 링크와 함께 적는다. 사용자 발언·에이전트 제안·AI 요약을 구분한다. 전체 대화나 로그는 복제하지 않는다. [한국어 문서 어댑터](../contracts/components.md#simple-english-문서-어댑터)로 문장을 점검한다.
3. 실제 구현 선택·실패 조건·검증 한계에서 다시 설명할 질문을 고른다. 개발 후 여섯 문항을 연습할 수 있지만 숫자를 채우려고 사소한 질문을 만들지 않는다. 사용자의 이전 설명은 출처를 연결하고, 새 답변이 없으면 `미응답`으로 둔다. 사용자가 답하면 원문 답변과 코드 근거를 대조해 강점·빈틈·다시 볼 위치를 같은 문서에 기록한다. 기능별 이해 상태를 바꿀 근거가 생기면 `task-evidence learning-review`에 전달하고, 그 결과를 다시 요약한다.
4. 과제 시작 때 초안을 만들고, 중요한 설계 변경·현재 기능의 인계·공동 E2E와 설명 뒤에는 **바뀐 부분만** 갱신한다. 최종 점검 때 전체 경로·결정·남은 복습 질문을 현재 코드와 다시 대조한다. 사용자에게 읽을 링크와 가장 중요한 열린 질문을 전달한다.

`ToolResult`에는 실제 갱신 경로, 대조한 출처·코드 기준, 오래된 근거·불일치를 담는다. 이 도구는 `verified`, `learning_status`, 다음 작업을 자체 판정하지 않는다. 복습 문서만 요청받았다면 작성 후 끝내고 사용자 답변을 완료 조건으로 삼지 않는다.
