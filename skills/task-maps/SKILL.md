# 같은 과제와 같은 지도를 읽게 하기

[공유 계약](../contracts/task-workflow-v1.md)의 `MapSet`을 읽는다. 입력은 과제·연결된 전체 계획·인수 기준·코드·기존 지도이며 출력은 두 지도와 변경 근거다. 단독으로도 사용할 수 있고, 작업 상태 전이는 호출자가 맡는다.

1. 과제 ID·버전과 관련 코드를 대조한다. 기존 지도가 있으면 유지할 노드 ID와 바뀐 경로를 찾는다. 코드가 없는 구조는 `계획`, 읽어서 확인한 구조는 `구현`으로 표시한다. 확인되지 않은 연결은 가정으로 남긴다.
2. 객체 지도에는 실제 프로젝트 용어로 객체/모듈의 책임, 공개 입력·출력·오류, 의존 방향을 담는다. `plan.md`의 중요한 결정 ID를 그 선택이 영향을 주는 책임·경계 노드에 연결하고 제안과 합의를 구분한다. 책임이나 테스트 경계가 모호할 때 [구성 요소](../contracts/components.md)의 `codebase-design`을 읽는다. 클래스가 없는 프로젝트도 모듈·데이터·함수 책임으로 표현할 수 있다.
3. 흐름 지도에는 진입점 → 처리 → 외부 경계/저장 → 관찰 가능한 결과와 관련 실패 경로를 담는다. 현재 과제에 해당하는 노드·간선을 강조하고 완료·현재·후속 작업을 문자와 형태로 구분한다. 객체 지도와 공통 노드 ID를 사용한다.
4. `mermaid-diagrams`를 읽고 두 `.mmd` 원본과 `maps/index.md`를 갱신한다. 색인에는 노드 ID, 실제 코드 위치, 관련 인수 기준과 결정 ID, 계획/구현 구분, `map_revision`, `code_ref`를 기록한다. 구현 후 갱신에서는 추가·삭제·변경된 책임/연결을 모두 대조하며, 차이가 없을 때도 확인한 코드 식별값을 남긴다.
5. 사람이 읽을 HTML이 요청되거나 이 협업 패키지에 필요하면 `visual-explainer`를 읽어 `maps/view.html`을 만든다. 두 원본의 노드·관계·버전을 그대로 반영하고 해당 스킬의 렌더 검사와 화면 확인을 수행한다. 기존 HTML의 변경 부분을 갱신한다. 해커톤·시험 대비에서는 첫 화면에 전체 흐름과 현재 위치, 작업별 구현 기록으로 이동하는 경로를 둔다. 각 작업 기록에 요구와 사용자 결과, 계획 또는 실제 입력→코드/객체→저장→응답 경로, 결정 이유와 열린 쟁점, 실패 조건, 검증 상태와 근거를 짧게 표시한다. 현재 작업은 구현 전에 합의된 경로·검증 지점을 `계획`으로 먼저 보여줘 사용자가 구현 중 읽게 한다. 구조·결정·검증 경계가 바뀌면 계획과 실제의 차이를 표시하고 사용자에게 갱신 사실을 알린다. 인계 때 실제 코드·Red/Green 근거를 계획 경로 옆에 `구현`으로 표시하고 차이를 기록한다. 후속 작업은 개요와 `미구현` 상태를 분명히 표시한다. **중요한 결정 모두**를 `plan.md`의 결정 ID로 묶어 선택·이유·대안과 조건·제안/합의/에이전트 선택/미확인 상태·영향받는 노드·구현 근거를 읽을 수 있게 표시한다. 현재 기능에 관련된 결정과 그 작업에 반영된 미확인 가정은 첫 화면에서 바로 보이고 나머지는 같은 HTML 안의 색인에서 찾게 한다. `plan.md`가 결정·가정의 원본이며 HTML은 요약과 링크다. 기능 내용·이해 기록은 해당 작업 MD를 참조하고 복습할 노드와 기능 검증 상태를 별도로 문자로 표시한다. 결정 설명·검증·학습 상태만 바뀌고 노드/간선 구조가 그대로라면 구조의 `map_revision`을 올릴 필요는 없다.
6. HTML의 설명 문장은 [simple-english 문서 어댑터](../contracts/components.md#simple-english-문서-어댑터)로 점검한다. 원본·HTML·현재 과제의 노드 ID와 지도 버전이 일치하는지 확인하고 `ToolResult`를 반환한다. HTML은 원본에서 자동 동기화되는 서비스가 아니므로 원본 변경 시 함께 갱신하고, 이미 열린 사용자 탭은 새로고침해야 한다고 알린다. 필요한 원본이나 렌더 수단이 없어 요청한 결과를 완성하지 못하면 `blocked`와 부족한 항목을 반환한다.

지도는 구조를 설명한다. 실제 기능의 통과 여부는 테스트·E2E 근거로 별도 확인한다. 이 도구는 다음 과제 선택이나 `verified` 판정을 수행하지 않는다.
