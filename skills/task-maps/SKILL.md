# 같은 과제와 같은 지도를 읽게 하기

[공유 계약](../contracts/task-workflow-v1.md)의 `MapSet`을 읽는다. 입력은 과제·연결된 전체 계획·인수 기준·코드·기존 지도이며 출력은 두 지도와 변경 근거다. 단독으로도 사용할 수 있고, 작업 상태 전이는 호출자가 맡는다.

1. 과제 ID·버전과 관련 코드를 대조한다. 기존 지도가 있으면 유지할 노드 ID와 바뀐 경로를 찾는다. 코드가 없는 구조는 `계획`, 읽어서 확인한 구조는 `구현`으로 표시한다. 확인되지 않은 연결은 가정으로 남긴다.
2. 객체 지도에는 실제 프로젝트 용어로 객체/모듈의 책임, 공개 입력·출력·오류, 의존 방향을 담는다. 책임이나 테스트 경계가 모호할 때 [구성 요소](../contracts/components.md)의 `codebase-design`을 읽는다. 클래스가 없는 프로젝트도 모듈·데이터·함수 책임으로 표현할 수 있다.
3. 흐름 지도에는 진입점 → 처리 → 외부 경계/저장 → 관찰 가능한 결과와 관련 실패 경로를 담는다. 현재 과제에 해당하는 노드·간선을 강조하고 완료·현재·후속 작업을 문자와 형태로 구분한다. 객체 지도와 공통 노드 ID를 사용한다.
4. `mermaid-diagrams`를 읽고 두 `.mmd` 원본과 `maps/index.md`를 갱신한다. 색인에는 노드 ID, 실제 코드 위치, 관련 인수 기준, 계획/구현 구분, `map_revision`, `code_ref`를 기록한다. 구현 후 갱신에서는 추가·삭제·변경된 책임/연결을 모두 대조하며, 차이가 없을 때도 확인한 코드 식별값을 남긴다.
5. 사람이 읽을 HTML이 요청되거나 이 협업 패키지에 필요하면 `visual-explainer`를 읽어 `maps/view.html`을 만든다. 두 원본의 노드·관계·버전을 그대로 반영하고 해당 스킬의 렌더 검사와 화면 확인을 수행한다. 기존 HTML의 변경 부분을 갱신한다. 해커톤·시험 대비에서는 첫 화면에 전체 흐름과 현재 위치를 보여주고, 현재 기능의 원본 요구·동작 경로·선택 이유·실패 조건·검증 근거를 짧게 연결한다. 공통 결정은 `plan.md`, 기능 내용·이해 기록은 해당 작업 MD를 참조한다. 복습할 노드와 기능 검증 상태를 별도로 문자로 표시한다. 설명 기록만 바뀌었다면 구조의 `map_revision`을 올릴 필요는 없다.
6. 원본·HTML·현재 과제의 노드 ID와 지도 버전이 일치하는지 확인하고 `ToolResult`를 반환한다. HTML은 원본에서 자동 동기화되는 서비스가 아니므로 원본 변경 시 함께 갱신한다. 필요한 원본이나 렌더 수단이 없어 요청한 결과를 완성하지 못하면 `blocked`와 부족한 항목을 반환한다.

지도는 구조를 설명한다. 실제 기능의 통과 여부는 테스트·E2E 근거로 별도 확인한다. 이 도구는 다음 과제 선택이나 `verified` 판정을 수행하지 않는다.
