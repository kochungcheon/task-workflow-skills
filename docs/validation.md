# 공개 패키지 확인 기록

확인일: 2026-10-30.

## 병렬 조사·현재 기능 집중

- 독립적인 읽기 전용 초기 조사를 한 계획 초안에 합치고, 구현은 현재 티켓 하나로 유지하도록 작성 스킬·공유 지도 계약을 갱신했다. 사용자가 구현 중 읽는 계획 경로와 인계 때의 실제 경로를 구분했다.
- `scripts/check.py` 통과: 작성 스킬 4개, 공개 의존 6개, 원문 파일 해시 79개와 이식 가능한 참조 확인. 설치 테스트 4개 통과. 변경한 작성 스킬 2개의 형식 검사 통과.
- HTML 워크플로우 그림 10개를 렌더했다. 390px·1280px 화면 검사에서 문제 없고 최소 라벨은 각각 12.01px·12.44px이었다. 첫 화면과 새 병렬 구간 그림 시트를 확인했다.
- 실제 180분 과제에서의 소요 시간과 사용자 맥락 유지 효과는 아직 측정하지 않았다.

## 작업별 HTML 기록과 SimpleEnglish 묶음

- HTML 지도의 T01–T04 작업별 기록에 요구·코드 경로·결정·실패·검증 상태를 구분했다. T01은 실제 코드와 로그, T02–T04는 미구현 개요로 표시했다. Chrome에서 T01 화면과 T02 펼침을 확인했다.
- `SimpleEnglish` 2.1.1의 스킬·참조·MIT 라이선스를 공식 커밋 `a6fcb4fde098b33617cc1578d151ebf58774b883`에 고정했다. 영어 문서에는 원문 규칙을, 한국어 문서에는 패키지의 한국어 명료성 어댑터를 사용한다. 세션 훅·출력 스타일은 설치하지 않는다.
- `scripts/check.py`는 공개 스킬 6개·원문 파일 79개의 해시와 작성 문서 참조를 확인했고, 설치 테스트 4개가 통과했다. 작성 스킬 4개의 형식 검사도 통과했다. 원문 `simple-english`는 `compatibility` 필드를 그대로 보존했으며, 현재 `quick_validate.py`는 그 필드를 허용하지 않아 형식 검사만 실패한다. 원문 `rule-catalog.md`의 끝 빈 줄도 원문 보존을 위해 유지했다. 설치 검사와 원문 해시 검사는 통과했다.
- 한국어 문장 품질과 실제 180분 진행 속도는 이 설치 검사만으로 증명하지 않는다. 현재 HTML은 화면과 링크·펼침을 확인했다.

## v1.3 · 사용자·AI 설계 문답과 지도 연결

- `task-design-dialogue`를 추가해 과제·코드에서 확인할 사실과 사용자 기술 결정을 구분했다. 티켓·갈림길 초안을 바탕으로 선행 결정부터 질문·반론·수정안을 주고받고, 최종 선택·가정·영향을 `plan.md`와 객체/HTML 지도에 연결한다. GPTaku `show-me-the-prd`의 초안 우선과 Matt Pocock `grilling`의 결정 의존관계를 참고했으며 원문 스킬은 복사하지 않았다.
- 4개 작성 스킬 모두 형식 검사 통과. `python3 scripts/check.py` 통과: 5개 공개 의존 스킬의 원문 73개 해시와 작성 문서의 내부 참조·개인 절대 경로 확인. 설치·경로 이동·재실행·충돌 보존 검사 4개 통과. 작성 파일의 `git diff --check` 통과.
- HTML 원본 2개를 렌더해 각각 그림 9개를 생성했다. Chrome에서 프로젝트 HTML의 첫 화면과 새 설계 문답 단계 표시를 확인했다. 렌더러 자체 화면 검사는 브라우저 시작 실패로 생략됐고, Chrome의 단계 버튼 클릭은 제어 세션이 바뀌어 이번 회차에 확인하지 못했다.
- 프로젝트·공개 패키지·전역 설치본의 작성 스킬 9개 파일을 대조했다. 실제 180분 해커톤, 새로운 설계 문답의 대화 품질과 구현 속도 효과는 아직 측정하지 않았다.

## v1.2 · 3시간 해커톤과 자기 설명 연결

- 전체 구현 양식, 원문 요구·결정 ID 연결, 기능별 learning-review, 복습 상태와 시간 배분 참조를 반영했다. 공개 의존 스킬의 원문·라이선스는 변경하지 않았다.
- 스킬 3개 형식 검사 통과. 검사기의 PyYAML은 기존 캐시에서 `uv run --offline --with pyyaml`로 준비했으며 패키지 런타임 의존성을 추가하지 않았다.
- 참조·개인 절대 경로·공개 원문 73개 해시 검사 통과. 설치 테스트 4개 통과. 경로 이동 검사에 전체 계획 양식과 해커톤 참조의 동반 설치 확인을 추가했다.
- HTML 그림 9개·캡션 9개, 390px·1280px 화면 검사 통과. 최소 라벨 12.01px·12.44px. 시간 배분 그림의 라벨 넘침을 수정한 뒤 재검사했고 생성된 첫 화면·그림 시트를 확인했다.
- JavaScript 문법, 8개 단계·4개 분기·4개 설명 상태·2개 변경 유형 버튼의 연결과 단계별 원문 경로를 검사했다. 브라우저 제어 호스트 연결이 불가해 이번 버전의 버튼 실제 클릭은 미검증이다.
- 일반 개발, 설명 미응답, 막힘을 남긴 진행, 명시적 설명 보류, E2E 실패 복귀, 변경된 코드/선택 이유의 재확인 조건을 문서상 대조했다. 실제 사용자 과제 실행이나 행동 시험을 대신하지 않는다.

## 최초 공개 패키지의 검증 기록

- 작성한 3개 스킬은 skill-creator의 형식 검사 통과.
- `python3 scripts/check.py` 통과: 공개 스킬 5개, upstream 파일·라이선스 73개의 SHA-256 일치, 내부 참조·필수 자원 확인, 작성한 문서의 개인 절대 경로 없음.
- 설치 검사 4개 통과: 한글·공백 경로 설치 후 다른 폴더로 이동, 동일 내용 재실행과 설치된 Node 자원 보존, 기존 사용자 파일 충돌 시 신규 복사 전 중단, dry-run 무변경.
- 새 임시 프로젝트에 전체 패키지를 설치하고 고정된 Node 의존성만 준비했다. 그 복사본의 렌더러로 `docs/workflow.src.html`을 실행해 `docs/workflow.html`을 생성했다.
- 렌더 결과: 그림 8개·캡션 8개, 390px·1280px 검사 통과. 최소 라벨 12.01px·12.44px. 생성된 첫 화면 시트를 직접 확인했다.
- 작성한 파일의 Git 공백 검사를 통과했다. 공개 원문에 있던 줄 끝 공백은 원문 보존을 위해 그대로 두며, 해당 파일은 잠금 파일의 해시로 동일성을 검사한다.

실제 사용자 과제의 TDD·공동 E2E·자기 설명 한 회차를 완료했다는 의미는 아니다. 네트워크 없는 문서 설치와 폴더 이동은 검증했고, HTML 렌더링은 Node 의존성과 브라우저를 준비한 환경에서 확인했다.
